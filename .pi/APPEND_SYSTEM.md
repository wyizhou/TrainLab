# 可选三角色适配：主 Agent 运行约定

本文件只适用于已确认在 Pi 中运行的主 Agent；协作职责、审核、并行、失败及交付流程仍以适用的 AGENTS.md 为准。根据宿主声明或当前运行时信息确认环境，不能因为项目存在 .pi/ 或机器安装了命令就认定当前环境。其他环境、无法确认的环境不执行本适配的接入检查或安装提醒。角色子 Agent 不执行下列主 Agent 检查、安装引导或调度。

## 首次检查与提醒

- 本会话首次轻量调用 `subagent({ action: "list", capabilities: true })` 和 `subagent({ action: "models" })`。核对精确名称 `agentsmd.planner`、`agentsmd.developer`、`agentsmd.validator`、实际来源及可执行性；应对应项目 .pi/agents/ 下的三个角色。短名、别名、同名其他来源及提示目录广告不能代替精确核对。必要时用 `action: "get"` 和来源文件核对路径、角色正文及生效配置。
- 接口不可见时，只说明可能未安装、未启用、未加载或工具受限；不要直接断言未安装。核实未安装后提供 `pi install npm:pi-subagents`，由用户决定是否安装。未经授权不安装、不修改全局配置，不绕过项目信任。已有配置先核对，不自动覆盖；安装、外部文件修改或信任变化后的加载方式见 README 的可选接入段。
- 发现就绪后简短告知：已预置这三个角色，可用 `model` / `thinking` 自定义；默认不需要额外模型配置。若已有自定义，说明实际生效值及来源，不再声称全部默认继承。同一会话无变化不重复提醒；模型、配置、工具或信任变化后重新核对受影响部分。
- 发现就绪不代表认证、额度或真实启动成功。缺角色、被禁用、能力受限、配置未加载或模型不可用时，不静默换成内置角色；普通讨论和只读查询可以继续，仅暂停需要该能力的协作派发，报告缺口。

## 派发前的模型与推理等级

1. 先读取当前扩展的实际解析结果和必要来源。模型选择尊重本次显式要求、项目/用户 settings 及 provider-scoped overrides、角色 YAML 和子 Agent 默认设置的真实优先级；保留已经选定的精确 `provider/id`，不猜别名或为了继承推理等级而改模型。
2. 已有明确推理策略时沿用解析结果，不用主会话等级覆盖。核对模型 `:level` 后缀、角色 `thinking`、`subagents.defaultThinking`、provider-scoped overrides、显式清除/禁用以及 `maxThinking`、模型范围等限制和适用范围。合法模型后缀优先于独立 thinking；`thinking: false` 是显式退出/清除，不等于 `off`。`models` 显示 `default` 或有效字段缺失，不能证明无人配置，必要时查实际 settings / YAML 来源。来源或含义不明先查明，不能擅自补齐。
3. **仅在没有明确推理策略时**，在主会话当次通过 shell 工具读取 `PI_REASONING_LEVEL`；可同时读取 `PI_PROVIDER`、`PI_MODEL` 核对当前会话。`model: inherit` 原生继承当前模型，但省略 thinking 不保证继承当前等级，保存的模型级/全局启动默认也不是当前等级证据。不得用子会话环境值冒充主会话值。
4. 保留已解析的精确模型，以本次派发的 `model: "provider/id:level"` 后缀补齐等级，不写回配置。工具顶层 `thinking` 不是派发参数。先确认该等级受模型支持且符合上限/范围；同模型可参考主会话当前有效等级，另一固定模型须查可靠能力信息。缺主等级、未知模型/等级、信息矛盾、不兼容或超上限时停止受影响派发并报告，不猜测、不静默降级。
5. 本节是主 Agent 的提示约定，不是程序级强制，也不是扩展原生自动继承推理等级。检查须区分配置发现、真实启动和实际生效模型/等级；实际等级可核对新子会话的 shell 环境与会话记录，不能仅凭请求字符串宣布通过。认证、额度或启动失败保留客观证据，按项目失败规则处理，不自动换模型或执行模式。

## 派发边界

- 精确选择对应的 `agentsmd.*` 角色，每次首次、修复、复验都显式 `context: "fresh"` 并创建全新实例；不用 fork、resume 或旧聊天，不通过 steer / follow_up 追加任务。按对应 subagent-templates/ 模板在首次给齐完整材料；空白模板不是任务，子 Agent 不自行调度。
- 每次已决定的多步或并行编排只用一个顶层原生异步 workflow。实际父级审核点在前一 workflow 完全终态之后：主 Agent 消费证据、审核并准备下一轮完整材料，再决定后续 workflow；不把整个功能硬塞进一次调用，也不把同一已知编排任意拆散。报告落盘、派发回执或 typed gate 成功都不等于父级审核完成；不让旧子实例等待审批或续聊。
- 三角色默认仅继承项目规则上下文，不继承全局 AGENTS 类上下文、不启用角色持久记忆；这不等于隔离所有全局设置或扩展。工具声明不是文件系统沙箱，Planner / Validator 的 read-only 标签不撤销 bash 等工具的写能力；写入范围与受审内容冻结按任务和 AGENTS.md 执行。
- 需要浏览器或其他扩展工具时，核对角色工具白名单和实际加载的提供方；缺工具应报告并按授权补齐、重新检查，不能跳过必要验收。
