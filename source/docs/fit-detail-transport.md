# FIT 细读：无损列式交接

这是 M12 的内部传输格式，不是新的运动分析，也不是完整模型 Launcher。
原始 `fit_detail_v1` 仍由 DetailHost 验证、缓存和落库；每周 20 次、单次 20 分钟及
1/5 秒粒度规则不变。没有按模型偏好删掉活动、区块或指标。

## 表格怎样保留完整事实

`fit_detail_table_v1` 把每个区块反复出现的字段名和值只写一次：

| 字段 | 含义 |
| --- | --- |
| `block_defaults` | 每一行共同拥有的字段和值，包含明确的 null、单位和覆盖信息 |
| `block_columns` | 变化字段的有序列名；点号表示原对象的层级，不是文件路径 |
| `block_rows` | 每个原区块对应一行；先复制 defaults，再按列名填入本行值 |
| `detail_sha256` | 还原后的完整 `fit_detail_v1` 规范 JSON 摘要 |

例如，所有区块的心率单位相同时只需在 defaults 中写一次；每行的心率均值仍逐项保留。
不会舍入、改单位、删除缺失值、重算分区或把区块替换为 AI 总结。多 session、暂停、
原始样本覆盖和全部来源字段仍能准确还原。空结果的列、默认值和行均为空。

解码后必须通过原始完整 Schema，再重新编码逐项相同；重复列、未知字段、错行宽、
不一致来源、错误 SHA 或损坏值都返回固定错误。校验失败不返回部分数据。

## SDK 与 Codex 的区别

默认 SDK 服务保持原 v1 返回；内部 `--compact` 只改变传输表示，不改变五个工具参数。
新 Codex 配置选择该模式，显式设置当前 CLI 支持的顶层 `tool_output_token_limit`。
本次值为 1,000,000，目的是不继续依赖本机观测到的约 12K 字符默认截断。
它不是模型总上下文长度的保证，也不能证明任意文件、20 次极大请求或任意模型都能装下。

`audit_model_output` 检查公开假端点实际收到的后续工具正文，而不只看完整 SDK 事件。
它只去除已观测的 CLI 耗时包装，要求完整 JSON 可解析、全部区块可逆、与 Host 原始结果
逐项相同。重复 JSON 键一律拒绝，不能把解析器覆盖掉的文字留给模型。哪怕另一个结果
自身 SHA 正确，只要不是本次 Host 结果，也必须拒绝。
截断或容量不足必须停止交接；不能把半份 JSON 当作可用证据继续写报告。

完整 Launcher 后续还要接入总上下文和运行回执；当前公开诊断通过不授权真实模型调用。
代码不读取测试目录，原数据库结果不迁移或覆盖。没有提供文件链接绕开细读边界。
