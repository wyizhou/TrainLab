# 模型进程证据保存

这是 [一次性模型账本](model-job-ledger.md) 内部的 Host 组件，不是新的运行命令、模型授权
或完整 Codex 启动器。它串联既有 [进程监督](model-process.md) 与
[结果协议](codex-output.md)，不再实现一套进程、重试或业务状态机。

## 输入与输出

`process_capture.binding()` 绑定原请求 SHA、Prompt 字节 SHA/长度与 stdout/stderr 上限。
路径由 Host 相对实例根解析，不进入业务绑定；没有模型可调用的任意文件路径接口。
工作目录必须专用，父目录由 Host 预建且为当前 owner 的 `0700` 目录。

`run(work, binding, launch)` 的 `launch` 只能来自已配置的 Host 启动层，返回既有
`ProcessResult`。这不是对该 callable 的 OS 沙箱：能力、认证、全局说明/Skill隔离和
实际 Codex 二进制绑定仍须由完整 Adapter 在启动前验证。本模块不会读取或复制凭据，
不会自行连接模型、Garmin 或 Gmail，也不能把一个成功的合成进程当成真实 AI。

启动层必须用同一 Prompt 和上限调用监督器。本组件检查返回的完整输入长度、输出上限及
停止状态；只有返回值不能证明模型服务实际收到多少字节，因此不宣称远端收件证明。

## 唯一一次与保存顺序

1. 外层模型账本先领取该周唯一 job，并释放 SQLite 写锁。
2. 原子建立专用目录，持久化 `intent.json`，然后才允许启动。
3. 调用既有监督器，保存 stdout/stderr 的原始字节（Base64）、长度、SHA及固定进程状态。
4. 明确停止的结果写 `capture.json`；停止未确认的诊断只能写 `interrupted.json`。
5. 文件经 `0600` 临时写入、fsync、原子改名及目录同步，再读回核对后才能返回。
6. Codex结果解析和业务/证据验证在其后执行；进程正常退出不等于周报成功。

原始stderr合法为空，不生成虚假一行日志填空；JSON容器本身非空。非UTF-8、换行和空字节
均原样保留，不替换、不截断成成功；监督器因超限保留的有界前缀只能属于失败证据。
默认stdout上限64MiB、stderr上限1MiB；显式上限与监督器已有接口一致，单路不超过64MiB。

## 中断、损坏与恢复

- 目录一旦存在，后续调用绝不再次执行 `launch`。即使崩溃在建目录后、intent之前，也只
  能保留不完整状态；是否未实际启动不会自动获得第二次机会。
- 已有完整capture可以纯本地恢复，重复耐久化屏障，不增加输出或重新启动。
- 没有capture、停止未确认、未知调用异常或本地保存失败会抛出 `EvidenceUnavailable`，
  它继承 `AdapterInterrupted`，外层账本不能误记为普通终态失败。
- 空文件、字段/类型/哈希不符、额外文件、两个互斥结果、错误owner/权限和链接均拒绝采用。
  有限落盘失败遗留的临时文件保留供诊断，不通过删除它们掩盖不完整。
- 跨目录复制完整owner-only证据后仍能恢复。不要把旧目录内容恢复到新的模型机会，
  也不要手动改写失败capture；全周机会仍由外层不可变账本控制。

原始输出只保存在私有实例，不进入Git、普通状态摘要或公开日志。本模块测试全部使用合成
字节及本地Python进程；真实Codex、平台隔离和业务发布另按M12适用前置门执行。
