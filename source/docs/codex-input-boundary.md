# Codex 周任务入口：能力前检

这是 M12 的内部配置和公开离线请求检查器，不是 `weekly` 命令或私人模型调用许可。
完整模型适配、跨平台启动隔离、目标/历史周报组合及任务结果账本仍需后续接入。

## 已解决的边界

`codex_boundary.configuration_arguments` 只生成本次子进程的配置参数，不修改用户配置、
不启动进程，也不读认证文件。路径由 Host 的 source/ 与显式实例根解析后传入，
不是模型工具参数，不绑定任何用户名、磁盘或部署位置。

配置关闭 shell、命令执行、浏览器、其他应用、子 Agent、记忆、插件和工具搜索，
关闭网页搜索、项目说明加载和会话保存。MCP 只登记预绑定的
[read_fit_detail](fit-detail-server.md)，沿用现有新库的范围、预算和缓存。

实际 Launcher 仍须使用 `--ephemeral`、`--ignore-user-config`、`--ignore-rules`、
`--strict-config`、`--sandbox read-only`、`--json`，并采用独立的任务目录。
这些参数**不能独自证明输入隔离**，不能直接把本模块配置拼成私人运行命令。

## 为什么还需要检查实际请求

2026-09-06 对本机 codex-cli 0.147.0 的公开合成诊断确认：

- `--ignore-user-config` 不会排除用户级 `AGENTS.md` 或本地 Skill 清单。
- `skills.config` 按目录禁用未生效；指定完整 `SKILL.md` 文件才生效。
  官方配置参考当前将其描述为目录，不能仅凭文档假定实际行为。
- 本次 macOS 诊断采用仅对子进程生效的读取限制，排除用户说明和全局 Skill 根；
  没有修改、复制或安装全局 Skill，也没有改写用户配置。
- 关闭其他功能后仍有 `update_plan`、`request_user_input` 和三个 MCP 资源发现辅助工具。
  它们不是 FIT 文件或 Provider 访问入口；真实拒绝行为仍要测试，不能只认工具名称。

这些是本机诊断事实，**不是 Linux Launcher 已验证或已交付的声明**。后续启动器不能照搬
macOS 专用诊断命令作为跨平台实现，也不能把缺少隔离能力解释为允许继续私人调用。

## 请求检查器

`audit_initial_request` 仅检查本地假服务收到的第一份公开合成请求：

1. 只允许上述五个辅助工具和一个 `mcp__fit.read_fit_detail`；拒绝额外工具、服务器、
   重复项及细读参数扩展。完整工具定义（包括描述及嵌套字段说明）绑定本次公开 CLI
   0.147.0 的能力摘要；定义发生变化必须重新进行公开能力检查，不只比较名称。
2. Host instructions 必须匹配；按 CLI 已实测的加载行为，仅去除该说明文件首尾空白。
   用户 Prompt 必须逐字相同，不对业务文本做宽泛规范化。
3. 模型输入只能有固定的只读权限说明、CLI 运行环境说明和 Host 提供的 Prompt。
   自动加载的用户说明、Skill 清单、其他消息或图片均拒绝。
4. 运行环境仅允许已知字段，工作目录必须等于本次任务目录；文件系统声明必须为只读。
   这里的临时工作目录是 CLI 的操作元数据，不是 FIT 路径、业务身份或可调用的文件入口。
   XML 注释、处理指令及声明一律拒绝，不能把解析器忽略的文字留在模型输入中。
5. 首请求采用已观测顶层字段白名单，拒绝 `previous_response_id`、`conversation` 以及
   其他额外上下文字段；可选模型参数必须匹配本次公开探针。传输用 metadata 不作为模型
   业务输入，也不输出其内容。本组件没有宣称支持任意模型配置或后续会话请求。

成功返回 `status=checked` 和请求摘要；它不是远端模型成功回执。返回中的调用数为该纯检查器
自身的调用数，不能代替整个 Launcher 的预算与外部调用账本。该函数不创建 pending、
不调用模型、不保存任何用户资料。

本模块不负责验证训练内容，也不以工具清单替代实际子进程拒绝测试。完整 Adapter 后续必须
绑定受测 CLI、启动配置和隔离环境；版本/能力不一致时先停止，不把旧检查结果长期复用。

运行时不读取该测试文件。历史首轮漏检与旧进程测试时序失败保留在开发计划。

命令拒绝、任意资源拒绝及未登记 Garmin 工具拒绝。请求与诊断日志不进入 Git。
