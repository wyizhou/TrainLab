# M12 周报输入与完整历史

本模块把每周分析需要的原料保存成一份可重放的内部 Host 快照；它不生成训练建议，不启动模型，也不发送邮件。
当前执行使用[两阶段接线](weekly-stages.md)。下表是全周原料，不可整份传给跑步规划；
规划使用stage_context的显式跑步投影，总结使用全部运动和本次原计划。旧保存格式不改写。

## 输入内容

| 内容 | 来源与处理 |
| --- | --- |
| 本周全部运动 | 已冻结的 `weekly_evidence`，包括所有运动类型、完整摘要/分段、圈段、来源、覆盖率及无 FIT 的限制；不按计划筛选 |
| 目标快照 | 明确实例根下的私有 `goal.md`；复用 [公开目标模板](../goal.module.md) 的严格解析，只提供结构化字段，不提供文件或路径 |
| 最多四份历史周报 | 新 SQLite 中成功模型任务归档的完整结构化结果；包含其原有计划、目标及正文，不再次压缩，不补造缺失周 |
| 有界细读身份 | 本周全部有 FIT 活动的已冻结 scope SHA；模型仍只能通过原五参数工具读取授权范围 |

周窗口沿用香港时间周日 15:00 至下一周日 15:00。历史报告按真实周期倒序选择，
结束时间不晚于本期开始时间；同一期及未来报告不能作为历史。当前计划背景保留在前一期
完整报告中；没有历史时不制造旧计划。业务输出模块仍须负责具体报告/课程格式和安全校验。

## 保存与恢复

- `weekly_history.archive(instance, period_end, validate_report=...)` 只读取固定模型 intent、
  成功结果、原始已完成 capture 和 scope，重新验证保存的响应 Schema 与必填业务校验，
  再追加 `weekly_report`。不接受外部结果路径，也不把仅有 JSON 的孤立文件当成成功报告。
- `weekly_context.freeze(instance, period_end, validate_report=...)` 要求先完成周运动证据冻结，
  再读取目标、选取历史、冻结细读范围，并追加 `weekly_input`。范围与材料 SHA 都落新库。
- 同一周重放读取原目标和历史快照，不重新使用现在编辑过的目标或后来补入的周报。
  搬动完整实例目录不会改变逻辑身份；已选 FIT、历史 capture 或账本不完整时停止。
- `weekly_context.validator(...)` 返回原料校验器；新模型入口使用 `stage_context.validator`：模型 intent 建立之前复验
  同一快照，拒绝删活动、改目标、换历史、改变 JSON 类型或夹带字段。
- 归档写入失败可从原成功模型结果再次进行本地归档，不再次调用模型。

所有文件仍服从新实例 `0700/0600` 与 Git 忽略规则。目标原文、原文件 SHA、主机同步账本和
路径不进入模型输入。A-022/VC-005 允许运动 GPS、坐标、路线、地点和活动名称进入新版输入；
不因这些运动内容停止。邮箱、凭据、认证信息、无关个人/设备编号和文件路径（包括 `file:` URI）
继续保护，不偷偷删掉文字。自由文本检查不是健康诊断或隐写检测，不识别任意无标签秘密。

目标和历史共用原文与只读 NFKC 扫描视图；明确标签的别名、冒号/等号及中英文引号采用
同一语法，嵌套对象保留键值关联。扫描不会回写原历史正文、计划或 SHA；也不依赖目标
解析器的附带规范化才能拦截。已冻结输入在重放及模型前检查时仍需通过这一边界。

结构层先验证闭合 Schema、来源与 SHA，再显式选择允许的运动字段，不会把新增 Host 字段
自动带进模型。文本层由同一输入检查器处理所有入口，坐标不再作为隐私禁项；真实定位的有效性
由 FIT 解析器检查。坏定位不变成有效事实，也不因此丢弃正常运动。

新版 `fit_weekly_context_v2` 与模型证据 v2 绑定 `fit-summary-2`；旧 v1 快照仍按保存版本验证、
重算及读取，不补写 GPS、不修改历史 SHA，不因版本升级重新获得细读/模型预算。
同周已有旧证据但尚无 Context 时，也继续完成旧版快照，不能暗中混用新格式。

活动名称从本次已接受 inventory 页的私有 MCP capture 明确提取，保留原文、观察时点、
活动身份、capture/intent SHA 和字段位置；不是 FIT workout_name，也不是 Garmin HTTP raw。
名字缺失不补查、不丢活动；冻结和重放复核原来源，不拿后来改名替换旧输入。

本地`weekly_history.archive`保存完整成功结果作为不可变证据，不代表内容自动获准传模型。
选中的任何历史不符合输入边界时整次停止，不跳过它改选其他报告；旧输入重放也不会自动
清洗、覆盖或生成新版本。检查错误只返回固定类别，不回显敏感正文。

## 接入边界与测试

两个接口中的业务校验器必须由 Host 按报告版本提供，不能由 AI 选择或省略。本模块只验证
保存与输入边界，不能把一个宽松 Fake 样例解释成真实课程已经合格。具体训练结果、PDF、
发布及 daemon 仍属于后续模块；不恢复旧每日健康分析或旧 M11 合同。

回归见 [周输入测试](../tests/code/contract/test_m12_weekly_context.py)，覆盖真实格式合成 FIT
到新库、全活动、历史选择、目标/报告隐私、权限、模型前检、失败恢复和跨目录零调用重放。
集中隐私矩阵见[输入隐私回归](../tests/code/contract/test_m12_input_privacy.py)，同时测试
目标、完整历史的结论/课程/嵌套字段、首次冻结、旧快照及真实模拟模型入口；不读取私人实例。
片段及单位对照见[路线片段回归](../tests/code/contract/test_m12_route_fragments.py)。
这些旧拒绝矩阵继续检验 v1；新版对应测试及变更理由见[运动数据开放映射](m12-location-admission.md)。

R3 的同源业务 Schema/Prompt、Host 统计、逐证据课程校验和只读完整报告见[周报业务合同](weekly-coaching.md)。原冻结格式、执行器和预算保持原接口，发布由后续模块实现。
