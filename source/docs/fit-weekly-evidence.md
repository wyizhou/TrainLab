# 本周运动证据冻结

这是 M12 内部离线数据模块，不是周报命令或 AI 适配器。它不读取目标、历史 AI 正文、
私人配置或旧库，不调用 Provider，也不安排课程或发送邮件。

## 数据从哪里来

Host 调用 `weekly_evidence.freeze(instance_root, period_end, sync_job_key)`。
根目录只在 Host 内解析；逻辑结果不包含绝对路径，实例搬迁后可以继续工作。

前置条件是新库已有完整的 [FIT 同步](fit-sync.md) 成功回执，包括：

- 同步请求、完整连续分页及 inventory，不能只有“查到活动”的中间状态；
- 每项活动的 FIT 或 Provider 明确表示无 FIT 的结果；
- Capture、FIT、文件清单、SHA、权限和数据库关系闭合；
- 查询日期覆盖整个周窗口的本地日期，记录的查询时点不早于周日 15:00。

同步时点表示这次请求声明的观察时间，不是 Provider 对每一页相同毫秒的原子快照，
也不证明将来不会出现迟到上传。历史回填和正式在线预算仍属于后续交付。

## 哪些活动进入本周

窗口为香港时间上周日 15:00（含）到本周日 15:00（不含）。
按 FIT **结束时间**归属，整个活动一起进入，不拆分、不按计划或运动类型过滤。
下周课程日期由 Python 固定为紧接着的周一至周日，此模块不写课程内容。

首次冻结会核验新库所有登记 FIT，使用[白名单解析器](fit-parsing.md)生成摘要、圈段和分段。
它不是只看当前查询返回的活动：例如开始时间早于上周日、结束于本周的长活动，
只要其 FIT 已登记，也会纳入并标记 `registered_fit_only` 来源。
多个 FIT 修订影响同一本期活动时阻断，不擅自选择其中一个；解析失败不静默丢弃。

| 情况 | 处理 |
| --- | --- |
| 本周结束的跑步、攀岩、力量或其他运动 | 全部纳入，按结束时间排列 |
| 结束时间恰好在左边界 | 纳入本期 |
| 结束时间恰好在右边界 | 留到下期 |
| 完整查询为空，登记 FIT 中也无本期活动 | 活动清单为空，不造训练数据 |
| Provider 明确无 FIT | 留在 `unplaced_no_fit`；只披露 inventory 日期，结束时间和周期归属未知 |
| 查询、下载或会话审计未完成 | 不冻结周输入 |

没有 FIT 的 inventory 行不能提供训练摘要，也不能被伪装成“无运动”。该列表可能包含
查询日期两端不属于本周的活动，因缺少可信结束时间，保留不确定性而非猜测归属。
周计数分别列出本期有效 FIT 活动数、未能定位的无 FIT 项数和同步 inventory 数；三者不可混同。

## 保存与恢复

新结果使用 `fit_weekly_evidence_v2`，在新库既有 `weekly_input` 文档中不可变保存，
同时绑定同步请求/回执、inventory、活动、FIT SHA 和解析 SHA。只有规范化 JSON
通过 Schema、日期、逐活动来源和计数校验后才在同一事务内落库。

v2 允许解析器提供实际定位，并在 activity_sources/unplaced_no_fit 附加活动名称及 capture 血缘。
只从本次已接受分页对应的唯一成功 MCP capture 提取 name；缺失、空白或错误类型明确标记，
不回退 Workout 名称，不为名字新增调用。registered_fit_only 没有该来源时保持缺失。
旧 v1 周保持原解析版本和字段；改版不能补写旧内容、重置周预算或触发模型重跑。

同一期只接受第一次冻结的原料：plan/summary分别从这份原料投影，不重复冻结或改写；
同一同步来源重放返回相同内容、SQL 行和数据库字节不增加；
另一同步来源不能改写已有冻结。后续新增 FIT 不加入旧周，但原先使用的 FIT 若漂移仍然阻断。
事务写入失败时周文档和新解析一起回滚，重启可安全重新进行确定性本地构建。

此模块没有创建模型 attempt 或调用[本地细读](fit-detail.md)。后续模块会把已冻结运动证据、
最多前四份完整周报、目标快照组合成模型输入，并另行验证实际模型能力隔离。

## 测试边界

`test_m12_weekly_evidence.py` 使用真实 CRC 合成 FIT 和 Fake SDK，经过实际 FIT MCP 适配器、
同步状态机和 SQLite，再进入本模块；不接触正式实例或用户凭据。覆盖完整/空/无 FIT、
半开边界、跨周长活动、未完成同步、修订冲突、文件漂移、权限/链接、事务失败、搬迁与重放。
