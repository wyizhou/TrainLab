# M11 v4 OpenDesign 内容交接

本文件只定义下一轮高保真设计应接收的内容结构；当前 M11 v4 不实施视觉设计、CID/MIME 或邮件发送。

## 共同原则

- Markdown 与低保真 HTML 来自同一个 Reader Content Model。
- 业务主题最多一层可见容器，不在卡片内继续嵌套卡片。
- 必须适配 375、390、430、600 和 672 px。
- 日报目标阅读 2～3 分钟、最多两张图；周报目标阅读 5～7 分钟、最多三张图。
- 图表只使用真实数组；缺失时隐藏，并用文字披露。不得使用设计样例值填充真实邮件。
- 活动范围、睡眠醒来日范围和计划范围必须分开显示。

## 日报固定顺序

1. `completed_activities`：昨日全部运动事实。
2. `health_recovery`：健康、睡眠与恢复分析。
3. `fixed_course`：今天的固定周计划原课，不含评价或调整。
4. `limitations_alerts`：数据缺失与独立安全警告。

## 周报固定顺序

1. `week_conclusion`：结论先行。
2. `health_recovery`：全周健康与恢复。
3. `all_activities`：全部实际运动清单。
4. `technical_review`：最多三项关键跑步技术复盘。
5. `plan_comparison`：简短计划与实际对比。
6. `combined_load`：跑步、攀岩与恢复联合判断。
7. `fixed_plan`：唯一固定的七天下周计划。

## 状态矩阵

| 状态 | 内容行为 | 视觉提示 |
| --- | --- | --- |
| `ready` | 数据完整，正常展示 | 中性积极，不暗示必须执行课程 |
| `caution` | 保留固定课程，独立披露恢复注意项 | 黄色或琥珀提示，不生成替代课 |
| `blocked` | 保留历史计划身份，明确健康红旗并阻断自动执行 | 红色明确警告，不删除或偷改计划 |
| 无活动 | 明确写“昨日/本周无已登记活动” | 不生成空图表 |
| 指标缺失 | 披露指标和日期缺口 | 隐藏对应 KPI/图表，不以 0 代替 |
| 技术不适用 | 显示方法不适用原因和局限 | 不显示伪造趋势或评分 |

## 图表规则

- 日报可选：设备已记录的历史心率分区时长占比、睡眠阶段、单次活动序列，最多选择两张。
- 周报可选：逐日睡眠、RHR/HRV、跑量/活动时长，最多选择三张。
- 心率分区只能来自 FIT/Garmin session `time_in_hr_zone`；不能从心率采样重新划区。
- 所有图表必须有文字标题、alt、数据日期、单位、缺失说明和纯文字降级。

## 开发交接产物

OpenDesign 完成后应交付：日报/周报 HTML 模板、375/672 px 截图、字段映射、CSS/间距/颜色规范、图表资产规则、ready/caution/blocked/缺失状态样例，以及一份说明“不得新增内容字段或动态改课逻辑”的 HANDOFF。
