# M11 Coaching Utility v2 冻结验收边界

本章程对应 A-015。它冻结内容返工的正确预期，不授权外部动作，也不得为了通过测试而降低。

## 处方边界

- 禁止输出或推导心率区间、目标 BPM、最大心率、阈值或 Z1–Z5。
- RHR、HRV、活动平均/最高心率可以作为已观测历史事实展示。
- 跑步执行强度以 RPE 和体感描述为主；可比历史证据存在时才可附加非目标性质的参考配速。
- `hold/advance` 周恰好一节条件性 SOS，默认星期三；`deload`、红旗或有证据的明显恢复不足可为零并须说明。
- 单独 `caution` 不得取消整周 SOS；每日只能维持、降级或取消原课程。
- SOS 跑步与高负荷攀岩合计不超过三次，日期差至少 3 天（如周一后最早周四）。
- 偏离星期三安排 SOS 必须引用日程或恢复理由。
- 历史参考配速只接受 Host `comparable_pace_reference_v1`：回顾日前42天内、已完成跑步、至少
  3 km/20分钟、覆盖率至少80%，且仅用于 recovery/easy/long；SOS 始终只使用 RPE/体感。

## 内容边界

- 每节课程包含目的、类型、剂量、热身、主训练、恢复、放松、执行提示、开始门、降级和停止条件。
- 日报同时呈现周计划原课、今日调整、昨日训练解读、健康/恢复解读与明确行动。
- 周报包含健康总结、运动/负荷总结、3–5 条观察→意义→行动洞察和七天详细计划。
- v2 周报只读精确七份 v2 日报和最多四份历史 v2 周总结，任何缺失或冲突均不重新读取 raw。
- 缺失、不确定、阻断与证据引用必须如实展示；不得补造指标或训练目标。

## 版本与副作用

- 新增 `daily_email_view_v2`/`weekly_email_view_v2` 等 v2 Schema、上下文、AI 输出、课程和渲染；
  v1 代码路由和历史字节保持不变。
- 验收使用合成夹具和仓库外 owner-only Candidate；不修改正式 `source/state`。
- 本批次 Provider 调用、Gmail 发送、Garmin/Workout/Sites/cron 调用均为零。
- 不删除测试、不增加 skip/xfail、不改变正确预期制造 PASS。
