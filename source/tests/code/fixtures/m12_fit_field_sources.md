# 匿名 FIT 字段来源回归

`m12_fit_field_sources.json` 内的 Base64 是官方 Encoder 生成的完整匿名 FIT 字节；每组
`fit_sha256` 校验原字节，不依赖私人 FIT、忽略日志、网络或 SDK 安装。它不含设备身份、GPS
或真实活动。使用 JSON 容纳匿名夹具，保留仓库对私人 `.fit` 文件的统一忽略规则。

生成基准为 Garmin `garmin-fit-sdk 21.214.0`，commit
`f0d86b18195dbdf9c5b2f135aad5d6ae541f5fbb`；wheel/Profile SHA 与官方链接在 JSON
`provenance` 中。生成与复核日期为 2026-09-10。三个 record 分别在匿名起点及其后
10、20 秒，session 经过时间和 timer 都为 20 秒，汇总 timestamp 为起点后 20 秒。

`expected_points` 的原数值来自关闭组件展开与心率合并的官方 Decoder；完整选项保存在
`decoder_options`。增强速度/海拔先于普通速度/海拔作为业务候选，而有效原字段整体先于
组件值。原字段为 FIT 无效哨兵时视为缺失，不使用该哨兵作为运动值。其他八个指标也逐项
对照官方原字段的单位和缩放。

压缩速度/距离按官方 Profile 的 `record.compressed_speed_distance` 定义：速度占低
12 位、scale 100，距离占其后 12 位、scale 16，并累计距离回绕。仅组件输入的预期还与
官方展开视图核对；存在原字段冲突时，不用可能覆盖原值的展开视图充当原字段依据。
`compressed-rollover` 的实际距离为 250、260、270 米，证明跨 12 位回绕仍保持累计语义。

16 组输入覆盖普通/增强字段两种顺序、不同数值、普通无效而增强有效、增强缺失或无效
时普通回退、全部无效、仅压缩组件、组件与显式距离冲突及无效原值后的组件回退。
每组还保存修复前 `fit-summary-1/2` 的完整摘要哈希、未缓存细读哈希及逐点原值，
用于精确重放检查；这些旧版本预期有意保留原算法行为，不代表 v3 正确预期。

常规测试仅使用已保存的匿名字节和固定预期，读取库仍为项目既有 `fitdecode==0.11.0`。
