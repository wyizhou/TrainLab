# TrainLab v3.2 完整视觉交接基线

日期：2026-07-15 · `design_rev: 5` · `version: 3.2` · 视觉变化：无

## 1. 交付目标与权威顺序

本版解决的不是“再描述一遍页面”，而是把原型中所有会影响实现保真的信息变成可测量、可定位、可复核的契约。实施方不得根据业务理解重排模块、扩大容器、改变背景层级或自行选择响应式网格。

发生冲突时按以下顺序判断：

1. 原始视觉事实：`TrainLab 运动分析系统.html`。
2. 可定位事实：`运动分析系统.dc.html`。它与原型视觉相同，只增加 `data-vc`。
3. 同一视口、同一状态的浏览器实测：`v3.2-视觉基线.json`。
4. 本文档中的规则和参数。
5. `基线截图/` 仅用于人工直观复核；精确值以 JSON 的 computed style 和 rect 为准。

任何设计变更都必须提高 `design_rev`。实现向本基线对齐不属于设计变更。

## 4. 全局壳层与响应式规则

- 应用顶栏固定高度 56px，背景 `panelNav`，下边框 `borderWeak`。
- mobile 不显示顶部功能导航和同步胶囊；显示固定底栏，高 60px，主内容底部预留 76px。
- tablet 显示顶部导航，不显示同步胶囊；desktop/wide 显示顶部导航和同步胶囊。
- `main-content` 是唯一主滚动区；分析页内部用满剩余高度，其他页按内容纵向滚动。
- 页面 max-width：运动列表 1280、运动详情 1180、健康/习惯 1180、分析 1200、连接器 1100、设置 760，全部水平居中。

## 5. 页面蓝图

### 5.1 登录

全屏径向渐变背景，中心列宽 400px、最大 100%。卡片 padding 28px，`panel + borderPanel + radiusCard`。字段顺序固定为用户名、密码、验证码；验证码输入和刷新块同一行；登录按钮满宽。测试使用大于 6 位的账号和密码以及正确验证码。原型可见说明仍为“密码 ≥4位”，本版不改视觉文案。

### 5.2 分析

desktop/wide：`212px session-rail + 18px gap + conversation`；mobile/tablet：不渲染会话栏，顶部使用“会话下拉 + 新建”。分析输入位于消息流末尾，非 fixed。

顺序固定：会话选择/标题 → 消息列表 → 数据范围与附带数据开关 → 可展开运动选择器 → 文本输入和发送 → 当前范围摘要。消息宽度：AI desktop/wide 82%，用户 68%；手机分别 100%/94%。AI 气泡 `panel + borderPanel`，左下角 4px；用户气泡 `accentDeep`，右下角 4px。

图表卡四态：loading、empty、ready-collapsed、ready-expanded。折叠高度实测 43px；展开后 390px 约 180px，不显示明细行；1280px 约 394px，显示明细行。异步 1100/1400ms 仅为原型模拟，不是性能指标。

### 5.3 运动列表

顺序固定：标题/条数/批量下载 → 类型筛选 → 列表 → 分页。不能把上传组件放进本页。

- mobile：卡片列，gap 10；卡片 padding `14px 16px`；卡内指标固定 4 列。
- tablet/desktop/wide：表格壳 `panel + borderPanel + radiusCard`，内层最小宽 960px，列定义固定为 `36 112 78 1fr 84 88 90 110 92 70`，窄时在壳内横向滚动。
- hover 仅数据行使用 `#16202F`；表头和分页不使用 hover 底。

### 5.4 运动详情

顺序固定：返回/标题/下载 → 首屏指标 → 图表/逐秒切换 → 图表或逐秒数据 → 指标分区 → 分段。

首屏指标 `repeat(auto-fit,minmax(130px,1fr))`：390 为 2 列 172px；768 实测 5 列约 135.6px；1280/1536 为 6 个有效列约 186.7px。图表和指标分区均使用 `repeat(auto-fit,minmax(min(340px,100%),1fr))`：390 单列 356px；768 双列 355px；1280/1536 三列约 382.7px。

逐秒数据 mobile 使用卡片；其他档位使用最小宽 820px 的表。图表坐标 `viewBox 0 0 340 112`；心率区间颜色依次为 textFaint/accent/success/warn/danger。无数据显示 `--`，不得用 0 替换。

### 5.5 健康与习惯

健康标签顺序固定：睡眠、体重、静息心率、HRV、习惯。睡眠柱 desktop/tablet 为 14 根，mobile 为 7 根；单柱从上到下为 REM、浅睡、深睡，段高为小时数×15px。

mobile 的健康数据使用卡片列；tablet 以上使用表格壳。体重、静息心率、HRV 的趋势卡参数一致：`panel + borderPanel + radiusCard + padding20`，SVG 高 130px。习惯页顺序为日期工具条、已记录数量、早上/中午/晚上/全天四分组；组内标签可换行，分组不能改成多列卡片网格。

### 5.6 连接器

这是最容易被实现错排的页面。唯一正确顺序是：

1. 页面标题与说明。
2. 可选冲突横幅。
3. `connectors-grid`，两张账号卡。
4. “文件上传”标题。
5. `upload-grid`，左拖入区、右已解析文件。

不得把文件上传移到连接卡之前，也不得把上传区做成全宽单卡后再放连接卡。

| 视口 | 页面宽 | 连接卡网格 | 上传网格 |
|---:|---:|---|---|
| 390 | 356 | 1×356，纵向 | 1×356，纵向 |
| 768 | 736 | 2×360，gap16 | 2×360，gap16 |
| 1280 | 1100 | 2×542，gap16 | 2×542，gap16 |
| 1536 | 1100 | 2×542，gap16 | 2×542，gap16 |

连接卡 padding 20、内部 gap 14。上传拖入区是 `#0E1524`，1px dashed `#3A4E70`、radius14、padding `36px 24px`；右侧文件面板是 `#121A28`、1px `#223049`、radius12。

授权弹窗：tablet 以上宽 390、padding24、radius14；账密态 1280 实测高 334，2FA 态高 453。冲突弹窗宽 620，1280 实测高 373。mobile 两种弹窗均为 380×844 全屏，无边框/圆角，padding `24px 20px`，内部纵向滚动。

### 5.7 设置

设置是 760px 居中单列，固定四组：账户信息、单位制、区间设定、AI 接口。四组均使用 `settings-group`，不得只给首组卡片背景，也不得改成桌面双栏总布局。

账户网格：390 单列 310；768 双列 333；1280/1536 双列 350。心率区间网格：tablet 以上固定 4×111、gap12、max-width480；mobile 保留原型 2 列。系统提示词是 AI 组内的可展开深色面板。

## 6. 交互与状态契约

- 主导航切换页面并清空运动详情；active 项使用 accent 半透明底或手机顶边。
- 类型筛选切列表并复位分页；批量下载只有选中项时启用。
- 运动详情的“图表/逐秒表”切换不改变其余详情布局。
- 健康标签切换共享同一分页器，并在切换时显示对应趋势/表格或卡片。
- 会话支持新建、切换、重命名、删除；手机/平板用 select，桌面/宽屏用 rail。
- 发送支持按钮与 Enter；Shift+Enter 换行。发送后依次出现用户气泡、typing、AI 气泡与图表卡。
- 连接器支持失败重试、连接授权、可选 2FA、同步成功、冲突处理。冲突选择默认保留中国区。
- 设置按钮、单位标签、提示词展开、API 测试和 toast 的状态均属于视觉契约。

## 8. 基线文件使用方式

`v3.2-视觉基线.json` 每个状态包含：视口、document 尺寸、当前 screen、全部可见锚点、矩形、display/position/grid/flex、gap/padding/margin/max-width、颜色、边框、圆角、字体、overflow、对齐、透明度和 z-index。`cardinality_by_state` 可直接用于测试预期数量。

截图使用固定视口模式，不使用 full-page 模式。原因是应用的 `main-content` 是内部滚动容器，full-page 截图会改变可用高度并造成非真实响应式重排。出现原生滚动条时，位图尺寸会扣除滚动条占用的像素；审计视口仍以 JSON 的 `viewport` 为准。长页面的完整结构由 JSON 中的 scrollHeight、锚点矩形和本文顺序共同定义。

## 9. 验收标准

实现验收至少执行以下检查：

1. 四个固定视口逐页截图比对。
2. 页面 max-width、左右居中、模块顺序、网格列数必须完全一致。
3. 每个可见锚点的背景、边框、圆角、padding、gap、字号、字重一致。
4. 动态状态至少覆盖本文第 2 节列出的状态。
5. 不允许 document 级横向滚动；表格壳内横向滚动属于设计行为。
6. 不允许用“功能相同”解释视觉顺序、容器宽度或背景层级差异。

几何自动比对建议容差：位置/尺寸 `±1px`，颜色通道 `±1`，文本抗锯齿不作为色块差异；网格列数、display、position、overflow、模块顺序和断点分支零容差。

## 10. 显式原型例外

390px 设置页的 `settings-zone-grid` 实测容器 310px，但两列轨道为 `190px + 190px + 12px gap`；页面内部 `scrollWidth=415px`，主滚动区 `scrollWidth=427px/clientWidth=380px`。这是原型既有状态，document 本身仍无横向溢出。本轮为了零视觉变更不修正；实现必须复现或先提交新的设计 revision，不能暗中改成单列后仍宣称 1:1。
