## 当前唯一字段设计

states/data.db中的weekly_report保存多份运动数据的完整AI文本总结。仅使用以下三列；不另加activity_id、week_id、周起止列、模型/状态/版本或报告元数据表。

| 字段 | 含义 | 类型 |
| --- | --- | --- |
| id | SQLite生成的自增报告ID，唯一标识一条周报告，不对应某场活动 | INTEGER PRIMARY KEY AUTOINCREMENT |
| run_time_utc | 本次实际运行、保存报告所采用的当前时间T，也是滚动七天范围的时间基准 | TEXT |
| summary | 该范围多份运动数据的完整AI文本总结 | TEXT |

- id不引用activities，不从某场活动SHA或周编号推导。新报告由数据库分配ID，不设“每个自然周只能一个ID”的额外约束。
- 自增不保证无间隙连续，失败/回滚不能被验收要求凑号。AUTOINCREMENT涉及的sqlite_sequence是SQLite内部系统表，不是第五张业务表；不另建应用计数器表。
- run_time_utc不是唯一键，不用它冒充报告ID；不因为相同钟点就覆盖另一份报告。保存重试/提交状态不确定的处理由宿主边界明确，不宣称自增ID自动解决幂等。
- summary完整按文本保存/读取，不截断、不再次摘要、不只存文件路径，不强制转为结构化JSON报告对象或附塞运行元数据。Markdown/中文/换行/表格等均保留为正文。
- summary不是FIT第2类summary_json，不以单场活动报告冒充多活动周报，也不覆盖其他表的数据。

## 运行时间与统计周期：已确认

令本条报告保存的run_time_utc为T，统计周期是**T往前七天至T**，起点可由T减七天得到，无需新增周期起止字段。

- T是本次真实运行所采用的当前时间，不是“所属自然周”标识、下次计划时间或固定的周日15:00整。周日下午三点只是用户举例，不构成启动定时任务授权。
- 例如本次实际时间是周日15:03，报告对应前一周周日15:03至本次15:03；不是周一零点至周日结束，也不回填为原定15:00。例子仅说明时间含义，不是实际运行记录。
- 存储采用UTC，与用户看到的本地时间区分；本地下午三点不能直接写成15:00Z。周期使用同一时区/时间基准计算，避免字符串比较混入不同时区。
- 取数、AI输入中的周期说明和报告保存必须使用同一个T。宿主需统一捕获并传递该时间；不能先按T0准备报告，再只改写时间为较晚T1而声称内容覆盖至T1。生成/写入耗时的具体协调在宿主实现中落实，不新增时间列掩盖不一致。
- 滚动七天不是上一自然周。不同运行的窗口可重叠，不自动恢复暂停M12的补发原周期、固定周键或旧调度。
- 时间边界包含规则、跨界活动和合法时间缺失/空窗口的纳入预期在数据组装合同中落实；不由存储任务猜测活动归属，也不扩大当前支持运动范围。
