# Garmin Web GUI规划审核

- 日期：2026-09-18；Planner workflow `6e91d4b5-4d27-48ad-9dca-ee12bc0b58d7`、child `f8cf017d-1f7c-49c4-adb5-513f88e32d9d`已结束。
- 决定：批准`auth-web-plan.md`的G4/T10～T15及GUI32-01～06映射。先单一全新Developer实现T10～T13，主Agent核实材料/版本后制作完整中性固定副本给全新Validator做T14，再亲自Chrome验收T15。真实操作继续归T9/T2，不重复编号，不预先完成。
- 目标：本轮真正交付Web可选国际/中国区、账号密码与需要时2FA、保存/维护/需重新登录状态；不再要求聊天选区或先CLI认证。认证面板与仪表盘/数据库/AI配置独立。
- 接口一次确定：`/api/garmin/auth`下GET session/status，POST login/mfa/cancel/maintenance/retry；严格JSON、统一envelope、安全白名单，存储/登录/维护三类状态分开。维护retry只解除临时暂停且按真实期限检查，不提供强制改期或无限重试。原10条业务路由保留，前后端路由集合/健康合同同批对齐。
- 数据所有权：一个Web生命周期持有一个认证服务；HTTP/运行态不直接读写tokenstore/garmin.json，不导入SDK/仓储。所有者补安全区域和内部代次观察，内部代次不向浏览器输出。CLI/同步是各自进程实例，共享仓储规则和跨进程锁，不谎称共享Python对象。
- 安全与范围：接受仅规范`http://127.0.0.1:8080`的生产访问、全站Host防护、认证前缀会话/精确Origin/CSRF/Fetch Metadata门以及固定安全错误；会话cookie是本地不透明标识，不是Garmin令牌。限制只服务当前本机单进程产品，不增加公网/代理/多worker支持。旧测试显式使用规范Host/真正lifespan，不在生产放宽testserver。阻止帧嵌入和引用泄漏作为该GUI安全接入的一部分。
- 维护：真实启动Web后，在ASGI lifespan内协调自动维护；导入/构造不读私人认证或启动线程/网络。等待可停止/唤醒，逐请求SDK超时不冒充整个登录或关服总超时；在途操作结束后再close，不取消await后丢弃仍写盘的worker。人工/撤销结果绑定代次，不被本地load成功洗掉；有界临时重试，用户可从GUI重试。
- 合同调整：原starts_background_jobs=false已不适合作为整个Web运行期声明，必须如实拆分构造/导入无副作用与lifespan维护能力/实际状态；AI/活动同步自动调度仍不启用。这是用户明确要求Web维护的必要接线，不是系统常驻授权。
- 实现参数：会话数/TTL、请求体16KiB和字段长度等按规划作为实现安全默认值，可在兼容正常登录的范围内选取并测试，不冒称用户指定；密码不截断/trim，MFA不限定六位数字。新增依赖、SDK升级和扩大部署范围均不在此次实施权限内。
- 检查：Chrome真实页面→真实本机HTTP→运行态/所有者→实际SDK（仅替换远端HTTP）→真实仓储；C01～C12中用户可见流程必须Chrome实际操作，Python补精确边界，不用route.fulfill伪造认证成功。认证测试关闭trace/HAR/video，截图仅取清空敏感输入后的状态；测试子进程亦阻断外连。
