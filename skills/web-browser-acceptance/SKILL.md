# 网页开发与浏览器验收

## 核心要求

涉及网页相关开发时，必须采用**受控 Playwright Chrome E2E 脚本/夹具及全功能浏览器验收**。

代码审查、静态检查、编译、单元测试和接口测试属于基础验证，不能单独作为网页功能完成或交付通过的依据。必须在实际运行的网页中操作并核验结果。

本技能仅由本 Markdown 文档组成；执行任务时所需的测试脚本、夹具和验收证据，在目标项目中按其现有约定维护。

## 适用范围

适用于页面新建、样式调整、交互开发、缺陷修复，以及影响网页行为的接口、权限、路由和数据处理变更。

验收范围依据本次需求和变更影响确定：

- 新建网页或整体交付：覆盖本次承诺的全部功能。
- 局部修改：覆盖修改内容、受影响的用户流程及必要回归。
- 仅涉及说明文档、且不影响网页行为的修改：无需启动浏览器验收。

“全功能浏览器验收”要求使用具备目标功能所需能力的真实 Chrome，验证完整用户流程。不得仅凭静态预览、页面截图或受限浏览器中的局部操作认定验收通过。

## 受控脚本与夹具

“受控”意味着测试过程可审查、可重复、可定位问题，并具有明确的操作边界。

1. **明确测试目标**：记录应用版本、访问地址、启动方式、Chrome 版本及必要环境条件。
2. **保留执行入口**：优先复用项目已有的 Playwright 测试体系；缺少时补充与任务规模相称的脚本及必要夹具，并记录运行方法。
3. **固定测试前提**：通过夹具准备测试账号、权限、数据和初始状态，避免依赖上次执行留下的偶然状态。
4. **隔离测试影响**：优先使用测试环境和独立测试数据；清理操作仅限本次测试创建且允许删除的内容。
5. **断言实际结果**：从页面入口执行用户操作，检查可见反馈及业务结果，不能仅以“点击成功”“请求已发出”或“脚本未报错”判定通过。
6. **保证执行稳定**：使用明确的元素定位和状态等待，避免靠固定等待时间、无条件重试或吞掉异常掩盖问题。

模拟数据和请求拦截可用于验证特定界面状态，但必须标明范围；其结果不能替代真实依赖下的完整流程验收。不得修改页面内容或伪造成功响应来制造通过结果。

## 浏览器验收内容

先将需求整理为“功能—操作—预期结果—证据”清单，再在 Chrome 中逐项执行。下列项目按实际功能适用，未适用项应说明原因。

| 验收维度 | 核验内容 |
| --- | --- |
| 页面与导航 | 页面可访问，路由、链接、刷新及前进后退行为正确 |
| 核心功能 | 主要用户流程可完整执行，最终结果符合需求 |
| 表单与交互 | 输入、校验、提交、取消、重复操作及交互反馈正确 |
| 数据与状态 | 展示与实际结果一致；涉及保存时，刷新或重新进入后仍正确 |
| 异常与边界 | 空数据、无效输入、加载失败、权限不足等相关状态处理正确 |
| 布局与可用性 | 在要求的视口下无明显遮挡、溢出或不可操作区域，键盘操作满足需求 |
| 浏览器能力 | 涉及上传、下载、新窗口、存储等能力时，实际执行并检查结果 |
| 运行情况 | 检查相关控制台错误、失败请求及资源加载问题，确认对功能的影响 |
| 回归检查 | 受变更影响的既有流程仍可正常使用 |

涉及前后端联动时，应通过“页面操作—请求处理—结果展示—必要的刷新或重新查询”核验完整链路，不能只检查接口响应。

自动化断言之外，还必须查看实际页面渲染。关键页面和交互状态应通过有界面的 Chrome 或实际运行截图进行视觉检查；截图不能替代功能操作和结果断言。

## 执行与修复

1. 明确验收清单、测试环境和数据前提。
2. 启动应用，准备或复用受控脚本与夹具。
3. 执行 Chrome E2E，检查页面表现、业务结果和相关运行错误。
4. 保留失败证据，定位并修复问题。
5. 重新执行失败用例及受修复影响的回归用例。
6. 根据实际结果形成验收结论。

修复前的失败与修复后的复测应分别记录。不得通过删掉断言、跳过失败用例、放宽预期结果或反复重试，将未解决的问题报告为通过。

## 验收证据与结论

验收记录至少包含：

- 被验收的版本、环境、浏览器及执行时间。
- 脚本与夹具位置、运行方法。
- 功能覆盖清单、预期结果和实际结果。
- 必要的截图、测试报告或执行追踪。
- 发现的问题、修复情况、复测结果和未覆盖项。

证据不得包含密码、令牌或不必要的个人信息。

| 结论 | 判定条件 |
| --- | --- |
| 通过 | 本次范围内应验项目均已执行并达到预期，证据可追溯，无未解决的验收失败项 |
| 失败 | 已执行的验收发现功能、交互、展示或结果不符合要求 |
| 无法判断 | 浏览器、环境、账号、依赖或数据不足，导致必要项目无法完成验证 |

若部分项目失败、另有部分项目无法执行，应分别列出，不得合并为“通过”。

Chrome 无法运行、关键流程无法执行或只能使用模拟依赖时，可以继续完成不受影响的开发和检查，但必须如实说明验收缺口，不得宣称网页功能已完成验收。
