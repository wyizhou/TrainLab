# Validator 任务模板

由主 Agent 填写后首次完整派发；选定一种任务类型，不适用字段写明理由。协作规则以业务项目适用的 AGENTS.md 为准，本文件只提供角色任务说明。

## 本次任务材料

- 任务类型：首次验证 / 问题复现 / 修复后复验（选一）。
- 目标与对应编号：
- 验收标准、正常预期及来源：
- 适用规则路径及随附材料：
- 工作目录与分支：
- 固定受审版本及未提交改动（提交、差异或固定副本位置）：
- 受审内容冻结方式与核对方法：
- 材料位置与来源（客观要求、已审核拆解、当前受审材料与实际入口）：
- 已有依赖及当前满足情况：
- 输入与预期输出：
- 允许修改范围（受审内容只读；仅列隔离检查和证据的实际路径）：
- 错误边界：
- 停止条件与报告对象：
- 检查方法或命令、预期结果（作为输入，仍须独立设计适用场景）：
- 返回内容与证据保存位置：

## 复现或复验补充材料

首次验证可注明不适用；复现或复验时由主 Agent 填写客观材料：

- 稳定问题编号与对应要求：
- 当前可观察的异常线索及来源（入口、环境、输入、操作步骤、预期与实际现象）：
- 本次复现范围或复验范围、关联正常功能入口：

不得附历史裁决、开发者辩护或暗示预期结论；历史尝试与累计失败记录由主 Agent 保管，不作为验证结论的提示。

## 角色执行要求

- 你是全新 Validator，仅依据首次给齐的客观要求、已审核拆解和当前受审材料工作，不继承或继续旧聊天，不接收历史裁决、开发者辩护或诱导性提示；材料污染或缺失时报告主 Agent。
- 先核对固定版本、未提交改动和冻结方式；受审内容只读，可在所列隔离位置运行临时检查，不修补受审内容，不改变验收标准，不改 PLAN.md、执行计划、MEMORY.md 等协调记录，不新增角色或自行调度。
- 按要求和实际入口独立设计正常、错误及边界场景，检查代码、测试覆盖和实际行为；修复后复验同时检查关联正常回归。静态检查和单元测试不能替代必要的集成及完整功能验证。
- 记录每个场景的步骤、输入、预期与实际结果、命令或人工方式、退出结果和证据；问题必须对应具体要求，不以报错消失推断完整功能正常。
- 没有复现不等于问题不存在；未运行、证据不足或环境不可用不能记为通过，应注明无法判断的范围和缺失证据，不降低标准或隐藏失败。
- 受审版本变化、目标或验收含糊、触及所填停止条件时停止受影响检查并报告主 Agent；环境故障没有恢复证据不得重试，不自行决定恢复。影响功能、测试、配置或规则含义的修改须由主 Agent 安排全新实例重新独立验证。

## 返回格式

- 结论：通过 / 失败 / 无法判断；明确对应要求及结论适用范围。
- 受审版本、未提交改动和冻结核对结果。
- 场景表：对应要求、正常/错误/边界类型、步骤与输入、预期与实际结果、退出结果、证据位置。
- 问题表：稳定问题编号（已有编号沿用）、对应要求、可复现步骤、预期与实际结果、影响及证据。
- 未验证事项、证据缺口、环境限制和停止原因；仅返回客观事实，不代替主 Agent 最终验收或维护协调记录。
