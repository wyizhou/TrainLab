# TrainLab v0.1.1

- 产品/前端版本：`v0.1.1` / package `0.1.1`
- 当前状态：发布候选，尚未创建 tag 或 GitHub Release
- 前端设计/实现基线：v3.4 / design_rev 7
- 后端组件版本：`0.3.1`
- 数据库迁移头：`0003_activity_data_lifecycle`

## 发布定位

v0.1.1 是 v0.1.0 的兼容补丁版本，集中修正真实 FIT 文件上传和运动详情表达，并统一本机开发凭据。它不增加新的外部数据源、数据库迁移或产品页面。

## 主要修复

- 文件上传区支持一个或多个文件拖放，继续复用点击选择的校验、FIT 持久化和 TCX/GPX 本地预览路径。
- 力量训练只按 FIT `set` 实例构建训练组，通过 workout step 与 exercise title 取得安全动作名；split 和 summary 不重复计数。
- 难度攀岩和抱石只按 `split` 实例构建攀爬/休息结构；summary 不计入实例。
- Garmin profile 未定义的 split 字段 69–73 保留用于审计和重放，但不会被猜成 V-scale、YDS、成功率或失败原因。
- 时间构成使用可访问的 SVG 圆环，百分比、图例和弧长由同一数据生成。
- 本机管理员可使用默认 dry-run、整批原子提交的 `reparse-fit` 更新已完成导入，同时保留资源 UUID、用户归属、标题覆盖和原文件。
- 本机 development 默认凭据统一为 `useradmin / useradmin`，账号和密码仍必须大于 6 位；公开凭据禁止用于生产或可被其他设备访问的环境。

## 兼容性

- 现有 `/api/v1` 路径和数据库迁移头不变；segment 新增的 `semantic` 为向后兼容字段。
- 产品和前端 package 升为 `0.1.1`；后端组件与 OpenAPI 独立升为 `0.3.1`。
- 新备份 manifest 标记 `v0.1.1`。恢复工具继续明确接受迁移头相同的 `v0.1.0` 备份，并继续拒绝未知版本、损坏校验和或不安全归档。
- 从旧开发凭据切换时使用 `set-development-owner`；命令保留 owner UUID 和数据归属并撤销旧会话。

## 升级

在真实数据环境升级前创建数据库和私有 FIT 卷的同停写点备份，然后从发布 tag 重建服务：

```bash
mkdir -p backups
chmod 700 backups
python3 backend/scripts/backup_release.py \
  --project trainlab \
  --output backups/trainlab-before-v0.1.1

backend/scripts/compose.sh up --build -d --wait db backend
curl --fail http://localhost:8000/readyz
```

完整备份、恢复和安全重解析步骤见 `docs/runbooks/backup-restore.md` 与 `docs/runbooks/local-development.md`。

## 已验证结果

- [PR #15](https://github.com/wyizhou/TrainLab/pull/15) 的 5 项 GitHub checks 全部通过，用户已完成实际页面人工验收。
- 三份实际 FIT 经过同停写点双卷备份、dry-run、整批原子重解析、重建和浏览器复验；资源 ID、所有权和原文件 SHA-256 保持不变。
- 力量训练为 10 个动作、30 个有效组、29 个休息段；难度攀岩为 5/5，抱石为 21/21。
- 多文件 DataTransfer 拖放、四档视口 SVG 圆环和真实登录回归均通过。

候选 PR 的最终门禁、独立 Validator、tag 和 GitHub Release 仍须按 `docs/plans/release-v0.1.1.md` 完成；仓库中存在本文件不表示已经发布。
