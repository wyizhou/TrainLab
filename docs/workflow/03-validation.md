# 阶段三：验收

## 目标

用可重复的证据证明实现符合本次验收标准。验收是每个开发任务的最后阶段，不再依赖独立 Validator 移动需求文件或合并分支。

## 自动化门禁

按改动范围先跑相关测试，交付前按风险运行：

```bash
npm run typecheck
npm run lint
npm run test
npm run e2e
npm run build
```

不得通过删除测试、扩大容差或降低规则等级来解决失败。

## UI 与视觉验收

涉及界面时：

1. 打开实现和 v3.2 原型的同一路径、同一状态。
2. 使用 390×844、768×1024、1280×800、1536×900 中适用的视口。
3. 对照整页截图检查页面宽度、居中、模块顺序、网格、留白和响应式重排。
4. 使用 `data-vc` 与 `v3.2-视觉基线.json` 检查关键 computed 样式和矩形位置。
5. 覆盖默认态以及任务涉及的弹窗、展开、错误、空态等交互状态。
6. 检查 document 级横向溢出，并记录原型已知例外。

## 独立复核

满足以下任一条件时，建议另开只读复核任务：

- 全站视觉对齐或大范围响应式调整。
- 登录、权限、数据安全、真实网络或后端接入。
- 跨多个领域的大型重构。
- 准备正式发布。
- 用户明确要求独立验收。

独立复核只检查并报告，不默认修改代码；发现问题后回到正常开发任务修复。
