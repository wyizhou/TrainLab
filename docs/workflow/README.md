# Codex 三阶段开发流程

TrainLab 的每个开发任务都按“规划 → 实现 → 验收”连续推进。三个阶段是固定质量检查点，但不要求三个独立 Agent 始终同时运行。

```text
用户需求
  → 任务分级
  → 规划：范围、风险、验收标准
  → 实现：单一工作区，或受控的集成分支 + 独立 worktree
  → 验收：自动门禁、浏览器和视觉核对
  → 交付
```

Agent 介入方式由任务风险决定：

| 任务等级    | 规划                                 | 实现     | 验收                    |
| ----------- | ------------------------------------ | -------- | ----------------------- |
| 小型        | 主 Agent                             | 主 Agent | 主 Agent                |
| 中型        | 主 Agent                             | 主 Agent | 独立 Validator 只读复核 |
| 大型/高风险 | 独立 Planner 只读审计，主 Agent 定案 | 主 Agent | 独立 Validator 只读复核 |

主 Agent 始终承担 Executor、集成与协调职责。默认由主 Agent 在单一工作区写入；只有大型任务经过依赖和文件所有权审计后，才允许把真正独立的交付单元分配到各自分支、worktree 和子 Agent。此时“唯一写入”按 worktree 生效，集成分支仍只由主 Agent 修改。中型及以上任务按分级直接创建对应的独立子 Agent，无需把角色重新变成常驻 harness。详细分级标准见根目录 `AGENTS.md`。

- `01-planning.md`：如何把需求变成可执行范围。
- `02-implementation.md`：如何在现有工程内完成实现。
- `03-validation.md`：如何证明结果满足功能和视觉标准。
