# ADR 0002：用户归属的本地 FIT 导入

状态：已采纳

## 决策

- 第一条真实运动业务闭环只接本地 Garmin FIT：认证上传、解析持久化、列表、共用详情、原文件下载和重试。Garmin Connect、TCX/GPX 后端导入、AI、Redis、队列和微服务不在本决策范围。
- 每个导入、活动及子表都显式保存 `user_id`；查询和修改同时按当前会话用户过滤，并以复合外键维护归属。跨用户对象统一表现为不存在。
- 上传流式计算 SHA-256，在同一用户内幂等；不同用户可以导入相同内容。只有 `complete/partial` 且存在活动时才可作为幂等成功；新鲜 `processing` 返回冲突，`pending` 或陈旧 `processing` 可由同文件重传安全接管，失败状态可以重试。
- 私有原文件使用服务端生成的用户 UUID/导入 UUID 相对键，固定在静态站点之外的受控根目录。路径解析必须同时验证根目录边界和当前预期用户 UUID，不能仅因另一用户的 key 格式合法就读取；目录和文件使用最小权限。Compose 用独立命名卷持久化，测试使用隔离临时目录。
- 私有存储拒绝文件系统根目录配置，数据库引擎隐藏 SQL 参数；未预见的文件系统、解析器或数据库异常都转换为无底层上下文的稳定错误。
- 解析在当前请求进程同步执行，不预先引入队列。状态包含 `pending/processing/complete/partial/failed`；行锁与陈旧时间门禁允许安全恢复进程崩溃留下的处理中记录。
- FIT 数据按活动/会话、采样、圈、set/split/summary、设备和指标定义分层保存。`split_summary` 作为摘要保留但不计具体实例；力量详情在存在 set 时不把平行 split 重复算作训练组。
- `time_in_zone_mesgs` 中 `reference_mesg=session` 的前五个 `time_in_hr_zone` 秒数按原始 FIT 值保存和展示，不根据设置页阈值重算；运动列表类型来自 FIT `sport/sub_sport`，不由详情 profile 反推。
- `device_info` 是状态快照。只按明确 `device_index`（含 creator）或安全哈希后的稳定身份合并；相同厂商/型号不足以证明同一设备，匿名消息保持独立。指标没有可证明来源时不绑定设备。
- 未建列的安全命名字段以 `native:<message>:<field>` 保存在 `extraMetrics` 并生成稳定 definition；坐标、身份和自由文本走专用字段或排除，避免重复和泄露。
- GPS 和活动时间仅向所有者返回；原始序列号不进入 API 或日志，只允许保存 SHA-256 摘要。外部真实样本只读验证，不进入仓库。

## 原因

该方案先形成可恢复、可审计的用户业务闭环，同时保留未来 Garmin Connect 和其他格式复用统一持久化层的空间。同步解析足以覆盖当前 50 MB 上限，也避免在尚无真实吞吐证据时增加队列运维复杂度。

## 后果

- 数据库迁移头为 `0002_activity_import`；就绪检查从 Alembic 单一 head 动态读取，避免硬编码遗忘。
- 数据库和私有原文件必须作为同一恢复单元备份；仅恢复其中之一可能产生 `raw_file_unavailable`。
- 前端设计/demo 模式仍可本地解析 fixture；只有 AuthProvider 在开发环境明确确认的 demo 模式才走本地 FIT，真实认证构建只通过后端导入。认证主体退出、失效或变化时会清空活动覆盖层和含 API Key/HR/FTP 的设置内存，避免同一 SPA 跨用户残留。TCX/GPX 当前仍是明确的本地演示边界。
- 真实认证界面不显示设计用假活动、假已入库行或 fixture 详情路由；列表/详情区分加载、空、404 与瞬时失败并支持重试。TCX/GPX 仅标记为“本地预览、未持久化”，列表行不可进入伪详情、不可勾选，也不提供 FIT 下载入口。
- 只有 `complete/partial` 导入会出现在活动列表和详情；重试失败时删除旧的活动投影并保留可重放导入记录，避免 `failed` 状态与仍可见旧详情互相矛盾。
- 未来异步化应复用现有状态机与 replay 元数据，不改变所有权、幂等和错误契约。
