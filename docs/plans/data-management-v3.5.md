## 1. 目标与非目标

本里程碑把后端 v0.3 已有的数据生命周期能力接入当前 React 界面，并严格对齐 v3.5 设计：运动列表和详情支持重命名、恢复解析标题、下载与删除；连接器页展示 FIT 导入记录、游标加载、重处理和删除恢复；设置页展示当前用户的存储与文件配额。所有新增界面覆盖 390、768、1280、1536 四档视口、键盘操作、异步状态和安全错误。

本轮不新增或改变后端业务 API、数据库迁移、主导航、Garmin CN Connect、AI、TCX/GPX 后端持久化、批量删除、搜索、配额管理或管理员界面。现有批量 FIT 下载模拟不在本轮产品化。

## 3. 共享 API 契约

设计文档中的部分字段是展示概念名，前端必须在 API 适配层映射真实 JSON，不能要求后端为原型重命名：

| 设计概念 | 真实 API 字段 |
|---|---|
| `fileName` | `originalFileName` |
| `fileSize` | `sizeBytes` |
| `attempts` | `attemptCount` |
| `usedFiles` | `fileCount` |
| 活动引用 | `activityId` |
| 导入标识 | `importId` |

冻结接口：

- `PATCH /api/v1/activities/{activityId}`，`{name:string}` 重命名，`{name:null}` 恢复解析标题。
- `DELETE /api/v1/activities/{activityId}`，成功 `204`。
- `GET /api/v1/imports?limit=&cursor=`，只使用 `nextCursor` 加载更多，不虚构总数或页码。
- `POST /api/v1/imports/{importId}/retry`，是否展示操作只看 `retryAvailable`。
- `DELETE /api/v1/imports/{importId}`，是否展示继续/重试删除只看 `deleteRetryAvailable`。
- `GET /api/v1/storage/usage`，消费 `usedBytes/fileCount/maxBytes/maxFiles/remainingBytes/remainingFiles`。

导入状态只允许 `pending/processing/complete/partial/failed/deleting/delete_failed`。跨用户对象继续返回不可区分的不存在结果；前端不得显示路径、存储键、堆栈或内部异常。所有写操作复用现有 CSRF 与登录失效处理，并防止重复提交。

## 4. 依赖图与交付单元

```text

 ├─ U-FE v3.5 前端数据管理界面
```

### F0 — 共享基础

- 唯一负责人：主 Agent，集成 worktree。
- 允许：本文件、`data/`。
- 禁止：产品源码、外部设计目录。
- 完成定义：设计摘要和 API 映射冻结；五个 FIT 名称、大小、SHA-256 可复查；工作区只有预期文件；提交后两个单元从同一提交分叉。

### U-FE — v3.5 前端数据管理界面

- 唯一负责人：Frontend Dev，独立分支与现有 Codex worktree。
- 依赖：F0 提交。
- 允许：`frontend/`，包括 API 适配、共享活动操作组件、运动列表/详情、连接器导入列表、设置存储卡、对应样式、单元/E2E/视觉测试和 v3.5 实现回归资产。
- 禁止：`backend/`、`data/`、根共享文档、设计目录、依赖锁文件（除非确有新依赖且先报告）。
- 功能完成定义：
  - 列表桌面表格与移动卡片、详情标题区复用同一活动菜单和管理对话框。
  - 重命名执行 trim、1–255 校验、busy/error/success；恢复发送 null 且不虚构预览；删除含级联与不可撤销说明，失败保留记录。
  - 导入列表完整消费七状态、两个 availability 布尔值和 cursor；首次/更多/刷新/空/失败/单条操作状态可测试。
  - 设置存储卡只展示快照，按字节与文件数表达正常、90% 接近、已满、空、加载和失败。
  - FIT 与 TCX/GPX 边界在上传、导入和存储区域一致。
  - 稳定 `data-vc` 锚点、菜单/对话框焦点行为、toast/alert/progressbar 语义和四档无 document 溢出全部满足设计。
- 单元验证：`typecheck`、`lint`、相关 Vitest、相关 Playwright、v3.5 四档视觉检查和 `build`。
- 失败回退：发现必须改后端契约时停止并报告，不在前端模拟第二套 API。

### U-BE — 五类真实 FIT 回归测试

- 唯一负责人：Backend Dev，独立分支与现有 Codex worktree。
- 依赖：F0 提交。
- 允许：新增或修改 `backend/tests/` 中专属真实样本测试；只读引用根 `data/`。
- 禁止：`backend/src/`、迁移、OpenAPI、前端、共享文档和 `data/` 内容。
- 完成定义：测试从统一根 `data/` 读取 run、hike、strength、lead、boulder；验证文件摘要、可解析、profile、稳定关键计数/语义和不泄漏原始定位/设备标识到测试输出。若现有实现与已发布契约不符，只报告缺口，不在本单元修业务代码。
- 单元验证：定向 pytest、后端 format/lint/mypy；测试在 CI 容器路径下可重复运行。
- 失败回退：真实样本断言不稳定时退回已证明的结构事实，不用放宽为“只要不抛异常”。

## 5. 集成与验收

主 Agent 按 `U-BE → U-FE` 接入，每次只接受已提交变更并运行相关回归。共享文件、动态状态、文档和最终 PR 只由主 Agent修改。

里程碑门禁：

1. 外部四个关键设计文件结束摘要与开始一致，且仓库中没有外部绝对路径。
2. 前端 typecheck、lint、全部单测、完整 E2E、v3.5 视觉、既有 v3.3/v3.4 视觉和 build 通过。
3. 后端 format、lint、mypy、全部 pytest、覆盖率、真实五样本定向回归和 OpenAPI 一致性通过。
4. Compose 真实登录下完成：上传/查看导入/加载更多/重处理可用态/重命名/恢复/下载/删除/存储快照；未登录与跨用户边界不回归。
5. 390、768、1280、1536 对照原型检查整页结构、菜单、三种活动对话框、导入主要状态和存储主要状态，无 document 横向溢出。
6. 独立只读 Validator 无 P0/P1/P2，发现问题由主 Agent修复并复验。
7. 通过阶段性 PR 合并 `main` 后同步并清理本次分支；不为 UI 里程碑移动 `v0.1.1` tag。

## 7. 风险与回退

- 真实 FIT 含健康、GPS 与设备信息，用户已明确授权进入远程；测试和文档仍不得打印原始轨迹、序列号或完整记录。
- 设计的展示名与真实字段不同，统一在前端边界映射；禁止静默漂移后端契约。
- 操作菜单同时影响列表行点击与详情导航，必须验证事件阻止、焦点归还和重复提交。
- 导入删除可能处于可恢复中间态；失败时保留记录并重新读取服务端事实，不能乐观移除。
- 视觉基线只有在当前外部设计实测、功能正确且四档验收后更新；不得以扩大容差制造通过。
