# TrainLab 第三层 Harness：60 项执行计划

状态：设计决策已逐项确认；本文是实施顺序、验收条件和回滚边界，不代表功能已经全部实现。

## 使用规则

- 生产分析只能通过 `trainlab run` 进入当前 Harness；不直接把数据库、原始 Garmin JSON/FIT、Gmail 或凭据交给分析模型。
- 所有时间、日期和日报/周报边界使用 `Asia/Hong_Kong`。数据库时间戳仍保存 UTC。
- 原始数据不可变，修订追加，报告、计划、事实和心率区间均保留版本。
- 外部邮件、FIT 字段、设备名称、天气文本和 provider 返回内容都是不可信数据，不能获得工具或文件执行权限。
- 本文的测试监督器只属于测试环境，不进入正式运行部署。

## 60 项清单

### A. 时间、报告和采集边界（01–12）

| 编号 | 执行内容 | 验收条件 |
|---|---|---|
| 01 | 日报日期 D 包含 D 的白天数据、D→D+1 主睡眠和 D+1 早晨恢复数据 | 契约测试覆盖跨午夜睡眠 |
| 02 | 日报固定在香港时间 09:00 发送，睡眠未完成也发送 | 邮件明确披露缺失/进行中 |
| 03 | 所有业务日期、睡眠归属、计划、展示和调度迁移到 `Asia/Hong_Kong` | 无 Singapore/UTC 混用断言 |
| 04 | 周报每周一 09:00 发送，回顾刚结束的周一至周日并规划当前周 | 周边界测试通过 |
| 05 | 09:00 后到达的迟到数据只修订数据和未来趋势，不自动改发已发送快照 | 明确区分 snapshot 与 revision |
| 06 | D+1 早晨只允许睡眠、早晨恢复相关的白名单信号，不引入当天步数/活动/卡路里 | 上下文字段白名单测试通过 |
| 07 | 所有运动类型均保留；跑步以外活动只影响负荷与恢复，不作为跑步里程 | 运动类型映射和计划约束一致 |
| 08 | 运动原始来源改为增量同步取得的 FIT，不依赖网页抓取运动详情 | 新活动必须有 FIT 绑定或明确缺失 |
| 09 | 天气按活动 ID 关联到运动；天气失败不阻止运动入库 | 缺失天气质量码可见 |
| 10 | 健康白名单仅保留睡眠、全天/静息心率、HRV、脉搏血氧、跑步 VO₂ Max、体重 | 非白名单资源不再进入采集计划 |
| 11 | 健康原始 JSON 永久保存，SQLite 保存规范化投影；AI 只读受限投影 | 原始值、单位、来源和 lineage 保留 |
| 12 | 数据请求按资源和覆盖状态判定；关键请求失败或开放缺口时阻止可能误导的建议并建立运维事件 | 失败路径不生成假完整报告 |

### B. 睡眠、FIT 和修订存储（13–22）

| 编号 | 执行内容 | 验收条件 |
|---|---|---|
| 13 | 主睡眠归属为醒来日期减一天；小睡按实际日期归属 | 跨午夜和多段睡眠测试通过 |
| 14 | 09:00 仍在进行的睡眠暂归前一日并标记 incomplete | 日报有进行中披露 |
| 15 | 新内容与当前内容相同则复用现有 revision；变化则追加新 revision，旧版不覆盖 | 内容哈希和 current 指针测试通过 |
| 16 | FIT 永久作为完整原始证据；解析 Session/Lap/Record/Event 和运动类型结构 | 解析器版本进入 lineage |
| 17 | SQLite 保存 session/lap/event、运动索引、集合和有界特征，不永久复制每秒 Record | 数据库体积和重建测试通过 |
| 18 | 默认 FIT 分析由本地确定性程序完成，AI 只收到紧凑结果和来源 | AI 输入不含完整 sample stream |
| 19 | 用户明确指定一个或多个 FIT 时，才允许把指定活动的完整解码消息交给 AI | 精确 activity ID 绑定、超限即拒绝 |
| 20 | 默认向 AI 去除设备序列号和精确 GPS；只有用户明确要求路线/GPS 分析时才放行 | 脱敏回归测试通过 |
| 21 | 原始 FIT、健康 JSON、来源 revision、确认计划和心率区间 revision 永久保留 | 任何清理任务不得触碰这些类别 |
| 22 | 可重建缓存和临时特征可清理；备份保留 7 个日备、4 个周备、6 个月备，迁移备份验证前受保护 | 备份轮换不删除 canonical 数据 |

### C. 数据窗口、分析上下文和证据（23–32）

| 编号 | 执行内容 | 验收条件 |
|---|---|---|
| 23 | 默认上下文窗口：短期 7 天、个人基线 28 天、趋势 90 天；180 天仅用于确定性心率区间 | 窗口不越权取原始数据 |
| 24 | 日报详细展示昨日活动；7/28/90 天只使用确定性汇总和特征 | 日报 context manifest 可审计 |
| 25 | 周报详细展示复盘周内所有活动及天气/运动特征，长期趋势保持紧凑 | 周报大小受控 |
| 26 | prior model output 只保存必要的结构化决定，不把旧长文当事实 | 当前事实优先级测试通过 |
| 27 | 日报接收完整当前 7 日计划并突出昨日/今日/明日；周报接收上一版计划和完成状态 | 模型不可改变计划匹配结果 |
| 28 | 确定性质量过滤先处理传感器尖峰、天气/暂停/失真并保留原始值与理由 | 质量 gate 与 source manifest 一致 |
| 29 | AI 只接收 schema 校验后的 JSON context、source_usage 和 quality_disclosures | 不可打开 DB、文件、网络或工具 |
| 30 | 正常目标上下文约 256 KiB，硬上限 1.1 MiB | 产生可测 size_bytes |
| 31 | 超限时按固定优先级裁剪，绝不移除目标日期、安全事实、当前计划、确认 HRR、质量和缺失披露 | 裁剪顺序和原因可重放 |
| 32 | 裁剪后仍超过 1.1 MiB 时停止分析，生成幂等运维事件并发送脱敏警告，不提高上限、不静默截断 | 恢复后才允许重试 |

### D. 用户事实、来源和心率区间（33–41）

| 编号 | 执行内容 | 验收条件 |
|---|---|---|
| 33 | 事实分为 `long_term`、`temporary`、`message_only`，并保留 pending/active/expired/suspended/revoked 等状态 | 状态迁移表有测试 |
| 34 | 用户明确报告的当前安全症状立即作为安全事实生效，即使日期未知；系统同时追问补充信息 | 不因缺少日期而忽略安全事实 |
| 35 | 提供邮件和只读 CLI 浏览 active/pending/future/expired/revoked 事实；修改/停用/撤销追加 revision，不物理删除 | FACT-ID 和历史可追溯 |
| 36 | 来源保留 provider_fact、provider_derived、user_asserted、derived_statistic、prior_model_output、unknown；删除未使用的 `provider_predicted` | acceptance_state 与 origin 分离 |
| 37 | 冲突按职责解决：raw 不覆写、质量过滤不改原值、用户症状控制安全、确认 HRR 为正式区间、AI 历史输出最低优先级 | 冲突矩阵测试通过 |
| 38 | Garmin VO₂ Max 原样保存；TrainLab 另算 HRR 主方法、历史阈值代理、Tanaka 低置信度对比 | Garmin 值不被本地替换 |
| 39 | HRR 使用 28 个有效健康日 RHR 稳健中位数、180 天跑步最大心率证据、90 天阈值跑证据及质量过滤 | 证据窗口和置信度可解释 |
| 40 | 最大心率候选必须有至少两次独立、持续、质量稳定的高心率证据并由用户最终确认；不使用单点尖峰或 Conconi 断言 | 无证据则 unavailable |
| 41 | 一行心率区间 revision 同时保存 HRR、阈值代理、Tanaka 三套结果，HRR 为主；仅用户请求时计算，确认后追加生效 revision | AI 只使用最新确认 HRR |

### E. 训练计划、目标和用户配置（42–49）

| 编号 | 执行内容 | 验收条件 |
|---|---|---|
| 42 | 训练难度全局 1–5，默认 2，是整体负荷目标而非配速倍率；恢复/安全规则覆盖它 | 输出与配置合同一致 |
| 43 | 马拉松和半马目标时间独立保存；各自可有目标日期，默认 null；`active_race_goal` 明确当前主目标 | 不从一个距离推导另一个 |
| 44 | 目标语义区分：时间无日期为长期改善，日期无时间为尽力提升，两者都有才尝试接近目标时间；不保证成绩 | 周目标记录可行性和不确定性 |
| 45 | 全局训练参数只能改现有 `config/trainlab.json`，不能通过邮件或 AI 修改；邮件最多提醒用户编辑文件 | 示例配置同步维护 |
| 46 | 每次分析启动时重新读取配置一次，生成带哈希的本次快照；运行中冻结快照，不跨任务缓存 | 修改后下一次任务生效 |
| 47 | 配置错误、字段冲突或非法日期/星期时停止本次分析，不沿用旧缓存，并建立运维事件 | schema/语义校验覆盖 |
| 48 | `available_training_weekdays` 规定允许跑步的星期；未列出日期严格休息；`preferred_long_run_weekday` 只是偏好且必须在允许集合内 | 周一=1、周日=7，按香港日期解析 |
| 49 | 计划只安排跑步或休息，不指定钟点；Hansons Marathon Method 固定，其他运动只影响负荷和恢复 | 每个跑步项目有可审计 session role |

### F. 可靠性、发布和安全运营（50–60）

| 编号 | 执行内容 | 验收条件 |
|---|---|---|
| 50 | 邮件失败后只重试发送，不重新同步或调用 AI；按 5 分钟、30 分钟、2 小时递增，之后最长每 6 小时一次；连续三次建立幂等事件 | 成功恢复只关闭对应事件 |
| 51 | 同一逻辑任务使用 lease/唯一键去重；日报、周报、FIT 分析互不误阻塞；过期 lease 可接管 | 并发测试无重复报告 |
| 52 | 服务恢复后最多自动补最近 7 份日报和 1 份周报；更早遗漏先停下并等明确范围 | 补跑按时间顺序且幂等 |
| 53 | “补录”生成缺失报告，“补发”复用已有版本，“重新生成”追加新 revision；旧内容不覆盖 | 三种命令的发送记录可区分 |
| 54 | 数据库迁移前保护备份，在事务中迁移并验证；失败回滚且新服务不启动 | integrity、外键和 schema 版本均验证 |
| 55 | 凭据、令牌和密码不进入 Git、DB 业务表、日志、AI、邮件或报告；Gmail 只用环境注册的 `gmail` MCP | 权限和忽略规则测试通过 |
| 56 | 邮件、附件、FIT 文本和 provider 内容先作为不可信数据；受限提取器只识别允许命令，文字本身不能执行 shell/文件/邮件操作 | 注入、转发、否定和引用测试通过 |
| 57 | 日志只记录任务 ID、日期范围、数量、revision/hash、耗时、状态和脱敏错误；不记录正文、健康原值、精确 GPS、完整 prompt 或凭据 | 日志扫描无敏感值 |
| 58 | README 记录用户可见规则；`docs/` 记录架构与状态机；`config/README.md` 记录字段和示例；清理历史矛盾文档 | 链接、契约和研究引用有效 |
| 59 | 建立单元、集成、迁移、并发、幂等、失败、注入、超限和本地端到端测试；模拟 Garmin/Gmail 默认不发真实邮件 | CI 和本地验收报告可复现 |
| 60 | 只在测试环境部署独立监督器，每 30 分钟检查进程、任务、DB、发件箱和异常；故障停服并保存事件，修复部署成功后重置 14 天；Codex 关闭时监督器不自动修代码 | 连续 14 天无程序故障才通过，正式环境不启用 |

## 实施顺序

1. **契约与存储**：时区、配置 schema、资源白名单、source/revision、事实状态、报告/任务幂等键和迁移收据。
2. **采集与投影**：增量游标、14 天重查、FIT 解析、天气一次调用、健康白名单、质量 gate 和 SQLite 投影。
3. **分析 Harness**：context manifest、窗口裁剪、HRR 三方法、计划/事实边界、结果校验和安全 gate。
4. **邮件与调度**：日报/周报窗口、补录/补发/重新生成、发件箱、重试、任务 lease 和错过任务补跑。
5. **文档与测试**：同步 README、配置说明、运行手册和历史矛盾文档；补齐第 59 项测试矩阵。
6. **本地验收**：不启动正式服务，先完成离线测试和数据完整性检查，再部署本地测试环境。
7. **14 天测试**：仅启用测试监督器；异常停服、修复、测试、提交、推送、重新部署并重置计时。
8. **发布**：14 天通过后才进行正式部署；所有提交、配置 schema、迁移和报告版本均可追溯。

## 不可越过的验收门

- 本地 `state/`、SQLite、原始 JSON/FIT 不因 Git 清理、迁移、测试或文档任务被删除。
- 未通过配置验证、数据质量 gate、安全 gate、上下文硬上限或幂等检查时，不生成可能误导的正式建议。
- 任何真实 Gmail 发送、远程部署或历史强制推送都必须有明确的当前任务授权，并在操作后重新核验。
