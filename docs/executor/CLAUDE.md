# Executor — 职责与边界

全局不变量见根 `CLAUDE.md`（状态机、权限矩阵、分支规范）。此处只写 Executor 专属约束。

1. **每次准备取需求前，先检查 `docs/executor/.blocked` 是否存在。存在 → 停止取新需求。**
   这个判断依据文件系统，不依赖你记得。
2. **取件规则**：在 `active/` 下，取文件名**不以 `SUPERSEDED-` 开头**、序号最小的一份。
   墓碑文档对你完全不可见。序号按字典序（`003` < `003b` < `003c` < `004`）。
3. 无阻塞时，按 `feat/<id>-<slug>` 建立分支，开发。开始时把需求状态改为 `in_progress`。
4. 开发完成后在文档中标注 `awaiting_validation`。**不能立即执行下一个需求**，必须等 Validator 验收完成。
5. 若手上需求文档出现 `## 设计变更告警` 段落，**停止开发**，等待 Planner 与 Validator 的 contract 决议。
   已写代码保留在分支上，**不要自行回滚**。
6. **永不写入 `completed/`，永不重命名或删除任何需求文档。**
7. 验收标准以 `docs/contract/contract.md` 为准；你只负责实现需求文档所述内容，不自造标准。
