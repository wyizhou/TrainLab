## 已确认的 FIT 时间与字段要求

- 新默认 `fit-summary-3` 的 session/lap 使用 `start_time + total_elapsed_time`（有限、非布尔、正数），不用汇总 timestamp 或 timer 兜底；record/event 保持点事件语义。非法/缺失时长、损坏输入和真实冲突仍拒绝或按现行局限披露。
- 旧 `fit-summary-1/2` 摘要、冻结周、scope、缓存和未缓存细读按原版本精确重放；新结果按 SHA+版本追加，存储不可变校验不变，不重置预算或重跑旧任务。
- 整秒 start 与毫秒 elapsed 的精度不同。只有正常顺序、唯一 session 归属的圈，严格小于 1 秒的相邻重叠或末端越界可视为精度相容并明确披露；这是项目处理，不冒称官方容差。保留公式原范围，不平移/取整/填洞，不当作完整 SOS 分区；圈统计仅取所属 session 的点和有效区间，细读保留裁剪标记。重复圈、同起点及大于等于 1 秒的实质冲突继续拒绝或 laps_conflicting，session 实质重叠门保持。
- 摘要、细读、压缩传输、周证据、周/阶段输入贯通 v3；旧 v1/v2 资源及位置/名称边界保留，不升级无结构变化的报告/发布格式。活动/session 消费者读取真实 UTC 小数秒并排序，周截止按精确结束时间比较；调度/授权日期仍用原整秒合同。
- v3 的真实 DetailHost 须读取毫秒尾段：start/end offset 为有限非负、毫秒精度数值，resolution 仍为原整数；1200 秒、20 次、归属/越界/预算检查不变。旧 v1/v2 整秒合同和缓存不变。
- v3 数值先按既有 enhanced/ordinary 候选优先级选择文件实际记录的有效原字段，再回退合法组件；不能将同名派生值误作原增强值，不能受字段排列影响。适用 record 数值字段含 distance，v1/v2、时间公式、额度、隐私和 Schema 合同保持。
